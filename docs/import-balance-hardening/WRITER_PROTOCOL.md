# Реестр финансовых writers и протокол

Статус «код защищён» означает прочитанный код и доступный smoke, а не завершённую многосессионную приёмку. Полный машинный реестр server writes / SQL lock-write mentions находится в writer-inventory.json пакета. Скрипт financialWriterInventory.cjs сканирует server/ и migrations/; динамические цели и ошибки parser сохраняются. ## Протокол

1. READ COMMITTED; fn_ledger_writer_lock получает transaction advisory lock `(7070,1)` **до любого FOR UPDATE/parent tuple**, receipt read и финансового DML. Gate живёт до commit/rollback.
2. Все поддерживаемые writers принимают тот же gate. Для direct autocommit DML стоят BEFORE STATEMENT triggers; trigger ledger alone недостаточен для RPC, уже захватившего parent row.
3. Дальше сохраняются локальные parent→child порядки RPC: debt→wallet, batch→ordered rows→matched transactions, wallet transfer→wallet UUID ascending. Глобальный exclusive gate исключает одновременную работу таких compliant writers. Это не доказательство единого более мелкого resource hierarchy для будущего redesign.
4. В одной операции multi-wallet ресурсы берутся детерминированно; не вводить wallet-first prelock перед gate. Ошибка SQLSTATE завершает failed DB transaction; API не утверждает, что весь многошаговый HTTP workflow откатился.
5. Привилегированный SELECT wallet FOR UPDATE до gate остаётся вне протокола. 40P01 через такой SQL не доказывает публичный endpoint deadlock. Новый RPC/delete/metadata fix проверен статически и single-session smoke; public race tests подготовлены, но не исполнены.

SQLSTATE 40P01/55P03/57014/40001 → controlled 409, no auto retry. Network loss → 503/unknown; клиент сохраняет ключ и требует status refresh. Отсутствующий guarded RPC → 503 без low-level fallback. Existing low-level service-only RPCs не являются публичным retry API. Direct privileged SQL обязан соблюдать протокол; отсутствие deadlock для любого SQL не обещается.

Gate сохранён. Предыдущие PG16/Node22 load данные (mixed50 p95 2.4–2.9 s; независимая B ждёт long import A около 2 s) относятся к **старому tree**, не capacity нового кода. Новый scope gate включает больше metadata/FK parents; overhead неизвестен. Redesign: сначала закрыть весь writer inventory, bridge/legacy shared-resource graph, multi-resource ordering и PG17 races; только затем отдельный tenant/resource lock протокол и сравнительный soak.

Основание механизма блокировок: [PostgreSQL 17 Explicit Locking](https://www.postgresql.org/docs/17/explicit-locking.html). Работоспособность этого патча подтверждают его проверки, а не наличие механизма в документации.
