# Accounting Core — architecture decision records (status: PROPOSED, 24 Oct 2026)

| ADR | Decision | Why | Rejected alternative |
|---|---|---|---|
| AC-001 | **Extend, do not replace.** The ledger is an accounting view over the existing cash subledger and registers. | The writer protocol, D4 anchors, reviewed import, keyed payroll and atomic payments are sound and tested. | A new financial system; rewriting `transactions`. |
| AC-002 | **No second cash record.** `transactions` stays the only cash record; GL bank lines reference transaction ids; GL bank balance must equal `fn_wallet_ledger_balance`. | Approved decision "one transaction, one original record, no shadow cash ledger". | Storing cash movements again in the journal as independent rows. |
| AC-003 | **Management views stay independent.** Pulse, Radar, burn/runway and the cash P&L keep their sources; the accrual P&L is a separate, labelled report. Any re-basing needs its own owner decision. | Never silently replace the cash management P&L with statutory accrual. | Switching Performance to the GL when it ships. |
| AC-004 | **Deterministic, versioned posting rules.** One rule module (JS) with SQL parity, `rule_set_version` on every entry; no keywords, no AI in posting; unknown → suspense with a review item. | Auditability; the keyword classifier already misstates revenue (I-1). | Posting from `classifyTransaction` results. |
| AC-005 | **Shadow first via an outbox, synchronous later.** Writers enqueue in their own transaction; a poster posts; live in-transaction posting only after validation, per company. | A GL defect must not block cash during the beta; atomic per entry either way. | Synchronous posting from day one. |
| AC-006 | **Company chart from a versioned template with stable keys;** reporting framework per company, confirmed by the accountant. | PT PMA does not imply a framework; SAK EP / SAK EMKM / SAK Indonesia differ by entity. | One fixed chart; inferring the framework from ownership. |
| AC-007 | **Functional currency per company and frozen FX snapshots;** tax (KMK) rates stored separately and never used for the GL. | UU KUP art. 28 / PMK 81/2024 (IDR unless USD permit); reproducible reports. | Valuing history at today's rate (current screens). |
| AC-008 | **Accounting start date + accountant-approved opening trial balance;** backfill only from the start date, idempotent, dry-run first. | No double counting of pre-start history; no uncontrolled backfill. | Posting the whole history automatically. |
| AC-009 | **Periods locked in the database;** reopen by owner/CFO with reason, audited, earlier snapshot kept. | Closed periods must be immutable for accountants and auditors. | A UI-only month-close checklist. |
| AC-010 | **AI and OCR are draft-only.** They may propose entries and mappings; a human approves; system entries come only from confirmed source rows. | Core invariant "AI explains, engines calculate"; no automatic final postings. | Auto-posting OCR-extracted bills. |
